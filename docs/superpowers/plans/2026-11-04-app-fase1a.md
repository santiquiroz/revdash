# Plan: app RevDash Fase 1a (sin hardware)

Spec: `docs/superpowers/specs/2026-11-04-app-revdash-design.md`. Proyecto Gradle en `android/`
(módulos `nucleo` JVM y `app` Android). Ya existen, y no se cambian sin avisar:

- `android/nucleo/src/main/kotlin/com/revdash/nucleo/Contratos.kt`: tipos compartidos (`TramaCan`,
  `FuenteTramas`, `Lectura`, `EstadoMoto`, `Odometro`, `MuestraVelocidad`, `Alerta`, `NivelAlerta`,
  `LadoAlerta`, `AlertasVisibles`, `EstadoDashcam`).
- `android/nucleo/src/main/kotlin/com/revdash/nucleo/perfil/`: `PerfilCan.kt` (modelo y `ClavesSenal`),
  `CodecPerfilCan.kt` (`CodecPerfilCan.leer(json): Result<PerfilCan>`), `DecodificadorSenal.kt`
  (`valor(senal, datos): Double?`, `texto(senal, datos): String?`; devuelven null si el valor es inválido o
  la trama es corta). Copiados de RevScope: no editarlos.
- Recursos de `nucleo`: `/perfiles_can/tvs.apache_rtr_160_4v.2024.json`, `/capturas/empujando.log`
  (30 s empujando la moto: velocidad de rueda de 0 a ~6 km/h) y `/capturas/acelerador_barrido.log` (10 s
  de barrido del acelerador: de 18,5 % a 100 %).
- Fuentes en `android/app/src/main/res/font/`: `barlowcondensed_bold`, `barlowcondensed_semibold`,
  `barlow_regular`, `barlow_semibold`, `barlow_bold`.
- Reglas visuales: `docs/diseno/sistema-visual.md`. Maquetas: `docs/img/mockups/*.html` y
  `docs/img/estado-*.png`.

Estilo para todas las tareas: Kotlin idiomático, funciones cortas que hacen una sola cosa y cuyo nombre lo
dice, sin KDoc (solo un comentario de una línea cuando el porqué no es obvio), datos inmutables (`data class`
+ `copy`), nombres en español como el resto del código, sin dependencias nuevas.
Pruebas con JUnit 4 y `kotlinx-coroutines-test` (`runTest`, tiempo virtual).

## Tarea A: tramas y perfiles incluidos (`nucleo`)

Archivos (paquete `com.revdash.nucleo.tramas` salvo que se diga otra cosa):

1. `tramas/ParserCandump.kt`: `object ParserCandump { fun linea(texto: String): TramaCan? }`.
   Formato candump: `(1793640325.016000) can0 301#0100FFFF02010000`. `tMs` = segundos × 1000 redondeado a
   Long. ID hexadecimal de 3 dígitos (11 bits) u 8 dígitos (29 bits). Datos hexadecimales de 0 a 16
   caracteres pares. Ignora espacios al inicio y al final. Devuelve null ante cualquier línea mal formada,
   tramas remotas (`ID#R`) o líneas vacías. Nunca lanza.
2. `tramas/ReproductorCandump.kt`:
   `class ReproductorCandump(lineas: List<String>, bucle: Boolean = true, reloj: () -> Long = System::currentTimeMillis) : FuenteTramas`.
   `tramas()` es un `flow`: interpreta las líneas una sola vez (descarta las null); si no queda ninguna,
   termina. Emite cada trama esperando con `delay` la diferencia entre su tiempo original y el de la
   anterior (sin esperar si es ≤ 0). Cada trama emitida lleva `tMs = reloj()` del momento de emisión (no
   el tiempo original). Con `bucle = true` vuelve a empezar tras una pausa de 10 ms; con `false` termina.
3. `tramas/CapturasIncluidas.kt`: `object CapturasIncluidas { fun empujando(): List<String>; fun aceleradorBarrido(): List<String> }`
   que leen `/capturas/empujando.log` y `/capturas/acelerador_barrido.log` con
   `CapturasIncluidas::class.java.getResourceAsStream(...)` (UTF-8). Lanza `IllegalStateException` con mensaje claro
   si falta el recurso.
4. `perfil/PerfilesIncluidos.kt` (paquete `com.revdash.nucleo.perfil`):
   `object PerfilesIncluidos { fun apache(): PerfilCan }` que lee `/perfiles_can/tvs.apache_rtr_160_4v.2024.json`
   y lo pasa por `CodecPerfilCan.leer(...).getOrThrow()`.

Pruebas (`android/nucleo/src/test/kotlin/com/revdash/nucleo/...`):

- `ParserCandumpTest`: línea válida de 11 bits (ID, tMs y bytes exactos); ID de 29 bits `18DAF110#0201`;
  trama sin datos `123#`; casos null (vacía, sin `#`, hexadecimal impar, más de 8 bytes, `#R`, basura).
- `CapturasConPerfilTest`: con `aceleradorBarrido()` y la señal `11` del perfil, el acelerador mínimo es
  ≤ 20 y el máximo ≥ 99. Con `empujando()` y la señal `VELOCIDAD_RUEDA`, el máximo está entre 5 y 7 km/h;
  con la señal `0D`, el máximo está entre 5 y 6 km/h. Toda línea de las dos capturas se interpreta (ninguna null).
- `ReproductorCandumpTest` (con `runTest` y `reloj = { testScheduler.currentTime }`): tres líneas separadas
  10 ms y 20 ms se emiten con tMs 0, 10 y 30 y la colección termina con `bucle = false`; con
  `bucle = true`, `take(6)` recibe las tres dos veces; una lista sin líneas válidas termina sin emitir.

## Tarea B: estado, odómetro y alertas (`nucleo`)

1. `estado/ProyectorEstado.kt` (paquete `com.revdash.nucleo.estado`):

   ```kotlin
   data class ValorCrudo(val numero: Double, val texto: String?, val tMs: Long)
   data class UltimosValores(val porClave: Map<String, ValorCrudo> = emptyMap())

   class ProyectorEstado(perfil: PerfilCan, claveVelocidad: String = ClavesSenal.VELOCIDAD) {
       fun aplicar(ultimos: UltimosValores, trama: TramaCan): UltimosValores
       fun estado(ultimos: UltimosValores, ahoraMs: Long): EstadoMoto
   }
   ```

   - `aplicar` decodifica todas las señales del perfil cuyo `id` (hexadecimal, comparar como número) sea el
     de la trama, con `DecodificadorSenal.valor` y `DecodificadorSenal.texto`. Si `valor` da null (inválido o
     trama corta), esa clave no se actualiza. Devuelve una copia nueva; no muta.
   - `estado` arma `EstadoMoto`: velocidad ← `claveVelocidad`; rpm ← `0C`; marcha ← texto de `GEAR`;
     acelerador ← `11`; temperatura del motor ← `05`; temperatura del aire ← `0F`; pata ← `PATA_LATERAL`;
     embrague ← `EMBRAGUE`; kill switch ← `KILL_SWITCH`; motor en marcha ← `MOTOR_EN_MARCHA` (banderas:
     `numero != 0.0`). Las señales por cable (direccionales, luz alta, check engine, ABS, combustible) quedan
     en `SinDato`.
   - Frescura: nunca recibida → `SinDato`. Velocidad con más de 500 ms de antigüedad → `SinDato` (no se
     congela). Cualquier otra señal con antigüedad > 3 × max(periodoMs de su señal, 50) → `Viejo(valor, tMs)`;
     si no, `Valor(valor, tMs)`. Antigüedad = `ahoraMs - tMs`.
   - Si el perfil no tiene una clave, ese campo queda en `SinDato`.
2. `estado/EstadosEnVivo.kt`:
   `fun estadosEnVivo(tramas: Flow<TramaCan>, proyector: ProyectorEstado, periodoMs: Long = 50, reloj: () -> Long): Flow<EstadoMoto>`.
   Con `channelFlow`: una corrutina consume `tramas` y actualiza los últimos valores; otra emite
   `proyector.estado(ultimos, reloj())` cada `periodoMs`, también cuando la fuente calla (así se ve el dato
   viejo). La primera emisión ocurre en t = 0.
3. `odometro/CalculoOdometro.kt` (paquete `com.revdash.nucleo.odometro`):
   - `fun Odometro.con(muestra: MuestraVelocidad): Odometro`: sin muestra anterior solo la guarda. Con
     anterior: dt = diferencia de tMs; si dt ≤ 0 o dt > 1000 ms no suma (hueco) y guarda la muestra; si no,
     suma la regla del trapecio `(v1 + v2) / 2 × dt / 3 600 000` km a `totalKm` y a `viajeKm`.
   - `fun Odometro.reiniciarViaje(): Odometro` (viaje a 0, total igual).
   - `fun debePersistir(guardadoKm: Double, actual: Odometro): Boolean` = `actual.totalKm - guardadoKm >= 0.1`.
4. `alertas/SeleccionAlertas.kt` (paquete `com.revdash.nucleo.alertas`):
   - `fun alertasVisibles(activas: List<Alerta>): AlertasVisibles`: `peligro` = la P1 con menor
     `tiempoAlChoqueS` (null cuenta como infinito; en empate, la primera); `advertencias` = las P2 en orden;
     `estados` = las P3 en orden.
   - `const val TOLERANCIA_LIMITE_KMH = 2.0` y
     `fun limiteSuperado(velocidad: Lectura<Double>, limiteKmh: Int?): Boolean`: true solo si hay límite,
     la velocidad es `Lectura.Valor` y supera límite + tolerancia.

Pruebas: `ProyectorEstadoTest` (perfil real con `PerfilesIncluidos.apache()` si ya existe; si no,
construir un `PerfilCan` mínimo en la prueba con 2-3 señales: trama 300 con acelerador 0x50 → 40 %, RPM
big-endian, marcha 0 → "N", valor inválido 7 en GEAR no pisa el anterior, velocidad a 501 ms → SinDato,
temperatura a 301 ms con periodo 100 → Viejo, clave ausente → SinDato, `aplicar` no muta la entrada);
`EstadosEnVivoTest` (tiempo virtual: emite cada 50 ms, refleja una trama nueva en la emisión siguiente,
sigue emitiendo sin tramas); `CalculoOdometroTest` (36 km/h constante durante 10 s en pasos de 100 ms →
0,1 km; hueco de 2 s no suma; dt negativo no suma; reiniciarViaje; debePersistir en 0,09 y 0,1);
`SeleccionAlertasTest` (dos P1 → gana menor TTC; P1 sin TTC pierde contra una con TTC; P2 y P3 separadas;
lista vacía; límite: null, SinDato, Viejo, 61 con límite 60 → false, 62,5 → true).

## Tarea D: lectura del protocolo RDP1 del ESP32 (`nucleo`)

En la Fase 1 la fuente real es el firmware de sondeo `firmware/probe/` (ya escrito) por USB serie a 921600
baudios. Emite líneas `RDP1` (ver `tools/rdp.py`, el parser de Python, y el plan de la Fase 0
`docs/superpowers/plans/2026-10-19-fase0-ingenieria-inversa.md`, Task 2):
`H,<ms>,RDP1,<fw>` · `S,<ms>,<perdidas>` · `E,<ms>,<canal>,<0|1>` · `F,<ms>,<canal>,<mHz>` ·
`C,<ms>,<id hex>,<x|s>,<datos hex, vacío si no hay>` · `K,<ms>,<hex>`.
Aquí solo va la parte pura; el acceso USB del lado Android viene después.

Archivos (paquete `com.revdash.nucleo.rdp`):

1. `rdp/EventoRdp.kt`: `sealed interface EventoRdp` con `Hola(ms: Long, version: String)`,
   `Estado(ms: Long, perdidas: Long)`, `Flanco(ms: Long, canal: Int, nivel: Boolean)`,
   `Frecuencia(ms: Long, canal: Int, milliHz: Long)`, `Can(ms: Long, id: Int, extendida: Boolean, datos: ByteArray)`
   (con `equals`/`hashCode` por contenido) y `Kline(ms: Long, datos: ByteArray)` (ídem).
2. `rdp/ParserRdp1.kt`: `object ParserRdp1 { fun linea(texto: String): EventoRdp? }`. Misma tolerancia que
   `tools/rdp.py`: busca el patrón `[HSEFCK],<dígitos>` en cualquier parte de la línea (el arranque del
   ESP32 deja basura antes), exige el número exacto de campos por tipo (H 2, S 1, E 2, F 2, C 3, K 1),
   valida hexadecimal par, nivel 0/1, `x|s`, CAN de hasta 8 bytes. Devuelve null ante cualquier error;
   nunca lanza.
3. `rdp/CanalesCable.kt`:
   `data class CanalesCable(val direccionalIzq: Int? = null, val direccionalDer: Int? = null, val luzAlta: Int? = null, val activoEnAlto: Boolean = true)`
   (los canales reales salen del pinout de la Fase 0; null = no conectado) y
   `fun EstadoMoto.conFlanco(flanco: EventoRdp.Flanco, canales: CanalesCable, tMs: Long): EstadoMoto`, que
   actualiza solo el campo cuyo canal coincide (`Lectura.Valor(nivel == activoEnAlto, tMs)`) y devuelve el
   mismo estado si ninguno coincide.
4. `rdp/TramasDeRdp.kt`:
   `fun tramasDeRdp(lineas: Flow<String>, reloj: () -> Long): Flow<TramaCan>`: interpreta cada línea y
   emite como `TramaCan(reloj(), id, datos)` solo los eventos `Can`.

Pruebas: `ParserRdp1Test` (un caso válido por tipo, CAN extendida con datos vacíos `C,10,18DAF110,x,`,
basura antes del patrón, campos de más o de menos, hexadecimal impar, nivel 2, CAN de 9 bytes → null);
`CanalesCableTest` (canal coincidente, activo en bajo, ningún canal); `TramasDeRdpTest` (mezcla de líneas:
solo salen las CAN, con el tMs del reloj).
