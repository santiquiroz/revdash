## Tarea K: reconexión del ESP32 (`android/app`)

Hoy, si se desconecta el USB, `lineasUsb` termina y la app no vuelve a leer aunque se reconecte.

1. `app/src/main/kotlin/com/revdash/app/usb/PuertoEsp32.kt`: agregar
   `fun lineasUsbConReintento(contexto: Context, esperaMs: Long = 1000): Flow<String>` = `flow { while (true) {
   emitAll(lineasUsb(contexto)); delay(esperaMs) } }`. Para no repetir el diálogo de permiso: en `lineasUsb`,
   si el usuario negó el permiso una vez (`EXTRA_PERMISSION_GRANTED == false`), no volver a llamar a
   `requestPermission` en esa ejecución del proceso (bandera en un `object` o `AtomicBoolean` de nivel de archivo);
   con la bandera puesta y sin permiso, `lineasUsb` cierra sin pedir nada.
2. `app/src/main/kotlin/com/revdash/app/demo/DemoTablero.kt`: usar `lineasUsbConReintento(app)` en lugar de
   `lineasUsb(app)`. Nada más.
3. `app/src/main/AndroidManifest.xml`: `android:launchMode="singleTask"` en `MainActivity`, para que conectar el
   ESP32 con la app abierta no cree otra instancia.
4. Verificar: `cd android && ./gradlew :app:testDebugUnitTest :app:assembleDebug`.

## Tarea J: receptor del duplicado dentro de RevDash (`android/app`)

Protocolo RDE1 en `docs/superpowers/specs/2026-11-04-duplicado-pantalla-design.md` (respetarlo byte por byte,
big-endian). La app compañera (`android/espejo`) es el servidor TCP en el puerto 27183; el tablero se conecta.

1. Código puro en `app/src/main/kotlin/com/revdash/app/espejo/ProtocoloRde1.kt`, con pruebas JUnit en
   `app/src/test/kotlin/com/revdash/app/espejo/ProtocoloRde1Test.kt`:
   - `data class CabeceraRde1(val ancho: Int, val alto: Int)`; `fun leerCabecera(b: ByteArray): CabeceraRde1?`
     (null si no son 8 bytes o no empieza por `RDE1`).
   - `data class EncabezadoPaquete(val tipo: Int, val relojMs: Long, val largo: Int)`;
     `fun leerEncabezado(b: ByteArray): EncabezadoPaquete?` (13 bytes; null si tipo fuera de 0..2 o largo < 0 o
     > 4 MiB).
   - `fun toque(accion: Int, x: Float, y: Float): ByteArray` (9 bytes; x/y recortados a 0..1).
   - `fun aNormalizado(xPx: Float, yPx: Float, anchoVista: Int, altoVista: Int, anchoVideo: Int, altoVideo: Int):
     Pair<Float, Float>?`: la vista muestra el video con proporción conservada y bandas (letterbox) centradas;
     convierte un punto de la vista a 0..1 sobre el video, o null si cae en una banda. Pruebas con vista 1000×600 y
     video 590×1280 (bandas a los lados), vista 1000×600 y video 1280×590, y un punto en la banda.
2. `app/src/main/kotlin/com/revdash/app/espejo/ClienteEspejo.kt`: clase con
   `fun conectar(host: String, puerto: Int, superficie: Surface, alCambiarEstado: (EstadoEspejo) -> Unit)` y
   `fun enviarToque(accion: Int, x: Float, y: Float)` y `fun cerrar()`. Hilo de IO: socket con `tcpNoDelay`, lee la
   cabecera, crea `MediaCodec` decodificador `video/avc` (`MediaFormat.createVideoFormat` con el tamaño de la
   cabecera, `KEY_LOW_LATENCY` = 1 en API 30+) con salida a `superficie`; por cada paquete: tipo 0 se pasa con
   `BUFFER_FLAG_CODEC_CONFIG`; los demás como cuadros (`presentationTimeUs` = relojMs*1000); suelta cada buffer de
   salida con `render = true` apenas sale. `enum class EstadoEspejo { CONECTANDO, VIENDO, ERROR, CERRADO }`.
   Las escrituras de toques van por una cola (un solo escritor) para no bloquear el hilo principal.
3. `app/src/main/kotlin/com/revdash/app/espejo/PantallaEspejo.kt`: composable con `AndroidView` de un
   `SurfaceView` a pantalla completa (fondo negro, video centrado con proporción conservada: calcular el tamaño
   con la misma lógica de `aNormalizado`), que al tener superficie llama a `conectar`. Toques del `SurfaceView`
   (`setOnTouchListener`: DOWN=0, MOVE=1, UP/CANCEL=2) → `aNormalizado` → `enviarToque`. Botón "TABLERO"
   (72 dp mínimo, estilo de los botones existentes, esquina inferior derecha) para volver. Texto de estado
   mientras no está `VIENDO`.
4. Navegación mínima: `ModoPantalla` gana `ESPEJO`; el botón de vista existente sigue rotando solo entre los
   tres modos de tablero; un botón nuevo "ESPEJO" en el tablero (junto al de vista, mismo estilo) entra al modo
   espejo. Host y puerto: constante `127.0.0.1:27183` por ahora (para probar con la app compañera en el mismo
   celular), en un `object ConfigEspejo` para cambiarla después.
5. No cambiar las capturas existentes de Roborazzi salvo por el botón nuevo (re-grabarlas con
   `:app:recordRoborazziDebug` si cambian y decirlo).
6. Verificar: `cd android && ./gradlew :app:testDebugUnitTest :app:assembleDebug`.

## Tarea L: CI en GitHub Actions

`.github/workflows/ci.yml`, en `push` y `pull_request` a `main`, tres jobs en `ubuntu-latest`:
- `android`: JDK 17 (temurin), `gradle/actions/setup-gradle`, `cd android && ./gradlew :nucleo:test
  :app:testDebugUnitTest :espejo:testDebugUnitTest :app:assembleDebug :espejo:assembleDebug`; sube los dos APK
  de depuración como artefactos. No correr `verifyRoborazzi` (las fuentes de Linux cambian los píxeles).
- `firmware`: Python 3.11, `pip install platformio`, `cd firmware/probe && pio test -e native && pio run -e
  esp32dev`.
- `python`: Python 3.11, `pip install pytest numpy`, `python -m pytest tools/tests` y `python -m pytest
  vision/tests` (si alguna prueba de vision necesita onnxruntime u opencv, instalar `onnxruntime opencv-python-headless`).
- Asegurar `chmod +x android/gradlew` en el job (o `git update-index --chmod=+x` no: solo el paso del job).
